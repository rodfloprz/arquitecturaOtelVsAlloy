<p class="lead">Evaluación para decidir cómo recolectar métricas, logs y trazas de una plataforma híbrida (Kubernetes y VMs, AWS y Azure) hacia Grafana Cloud, con GitOps y Terraform, y con preferencia por reducir el vendor lock-in.</p>

Fecha de investigación: **21 de octubre de 2026**. Este informe responde al prompt maestro de evaluación y absorbe la extensión sobre arquitectura híbrida, Fleet Management y gobierno centralizado. Cada página es una sección; se navega con el índice, con los botones inferiores o con las flechas del teclado.

### Cómo leer las etiquetas

| Etiqueta | Significado |
| --- | --- |
| {{V}} | Leído en documentación oficial, código o notas de versión durante esta investigación, con enlace |
| {{I}} | Deducción razonable a partir de lo verificado; se declara como supuesto |
| {{N}} | No se encontró evidencia oficial o la fuente es de terceros; no sustenta una recomendación |
| {{GA}} {{BETA}} {{ALPHA}} {{PV}} {{EXP}} | Estado de madurez del componente según la documentación del proyecto |
| {{ALTA}} {{MEDIA}} {{BAJA}} | Confianza de una conclusión: alta si hay documentación oficial concordante, media si hay una sola fuente o inferencia, baja si depende de una hipótesis a validar en piloto |

### Resultado de compatibilidad en las matrices

| Resultado | Se usa cuando |
| --- | --- |
| {{EQ}} | Ambas alternativas habilitan la funcionalidad con el mismo trabajo de fondo |
| {{EQC}} | La alternativa lo logra, pero necesita componentes que no vienen en el collector |
| {{PAR}} | Se obtiene una parte de la funcionalidad |
| {{NOEQ}} | No existe un camino equivalente en esa alternativa |

<div class="note"><p>Las cifras de esfuerzo en días-persona son estimaciones del analista con supuestos declarados; no son benchmarks. Ninguna conclusión de rendimiento (throughput, CPU, memoria) se sustenta en pruebas propias: la página de piloto define las pruebas que faltan.</p></div>
