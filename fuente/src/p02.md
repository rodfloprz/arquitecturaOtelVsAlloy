<p class="lead">Ninguna de las dos distribuciones es superior en todo. Alloy gana en operación, Kubernetes, Prometheus y funcionalidades administradas; Contrib gana en portabilidad de la configuración y en amplitud de componentes upstream.</p>

| Dominio | Conclusión | Confianza |
| --- | --- | --- |
| Distribuciones | Alloy es una distribución de OpenTelemetry Collector con pipelines Prometheus nativos; Contrib sigue en versiones 0.x con cambios incompatibles frecuentes entre releases | {{ALTA}} |
| Fleet Management | Soporta ambas; Kubernetes oficial solo documentado para Alloy; el Supervisor no revierte configuraciones inválidas por sí solo | {{ALTA}} |
| Discovery | No existe un único «discovery service»: en Alloy son componentes `discovery.*` más clustering; en Contrib, service discovery del receiver Prometheus más Target Allocator del Operator | {{ALTA}} |
| Métricas de infraestructura | Alloy es más directo; Contrib funciona pero el receiver Prometheus es beta, con funciones rechazadas y reparto de scrape que depende del Target Allocator | {{ALTA}} |
| Logs | Alloy es el cliente de logs soportado por Grafana; Logstash, Fluent Bit, Fluentd y Vector son clientes comunitarios sin soporte de Grafana Labs | {{ALTA}} |
| Trazas | Equivalentes en capacidades de tail sampling y balanceo; Alloy carece de `groupbytrace`; ninguna ofrece garantía de completitud ante cambios de topología | {{ALTA}} |
| Span metrics | Dos fuentes válidas para Application Observability: metrics-generator de Grafana Cloud o conectores locales; los nombres de métricas difieren | {{ALTA}} |
| Esfuerzo operativo | El esfuerzo humano de gobierno es lo que más separa a las opciones: 82 a 123 días-persona con Alloy frente a 164 a 246 con Contrib en 36 meses | {{MEDIA}} |
| Rendimiento | Sin datos comparables; requiere pruebas de carga | {{BAJA}} |

### Recomendación preliminar

1. **Agente estándar:** Alloy, motor por defecto, en EKS, AKS, EC2 y VMs de Azure.
2. **Métricas de infraestructura:** `prometheus.scrape` con clustering y `remote_write` a Grafana Cloud Metrics.
3. **Logs:** migrar a Alloy donde Loki sea el destino principal; conservar Logstash donde existan pipelines complejos o salidas múltiples, enviando a Alloy.
4. **Trazas:** OTLP de extremo a extremo; tier de balanceo y tier de muestreo separados; Adaptive Traces como alternativa cuando enviar el 100 % de las trazas a Grafana Cloud sea aceptable.
5. **Span metrics:** generadas en Grafana Cloud por defecto, con conectores locales solo para el escenario de máxima portabilidad.
6. **Contrib:** gateway acotado únicamente si el inventario de componentes revela una necesidad real.

<div class="note"><p>La recomendación cambia si la portabilidad pasa a ser el criterio dominante (la página de puntuación muestra el punto de cruce) o si el piloto revela fallas de Alloy en el volumen real del cliente.</p></div>
