<p class="lead">Para un destino principal en Grafana Cloud Logs, Alloy es el único cliente de la lista que Grafana Labs desarrolla y soporta; los demás son clientes comunitarios o de terceros. Eso no demuestra que Alloy sea más rápido ni que consuma menos: no existen benchmarks comparables, y esta página define las pruebas que faltan.</p>

### Lo verificado

- Grafana lista a Alloy como el cliente que desarrolla y soporta para Loki; Fluent Bit, Fluentd, Logstash y Vector se documentan como clientes comunitarios o de terceros y Grafana Labs no puede dar soporte de esos clientes {{V}}.
- Grafana no recomienda el plugin `logstash-output-loki` en despliegues nuevos y recomienda Alloy {{V}}.
- Loki ingiere logs OTLP por HTTP de forma nativa {{V}}; el OTLP endpoint de Grafana Cloud promueve atributos de recurso a etiquetas de logs con una lista configurable aparte de la de métricas {{V}}.
- `loki.write` de Alloy tiene un bloque `wal` para persistir entradas en disco; sin WAL, un corte largo de Loki puede perder logs al agotarse reintentos y buffers {{V}} (fuente comunitaria para el comportamiento).
- Para logs de Kubernetes, `loki.source.podlogs` y `loki.source.kubernetes` leen por la API de Kubernetes y consumen más red y CPU de los kubelets que `loki.source.file` {{V}}.
