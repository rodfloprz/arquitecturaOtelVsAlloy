<p class="lead">En ambas nubes hay tres caminos para métricas y logs de servicios gestionados: telemetría OTLP desde las aplicaciones, integraciones administradas de Grafana Cloud (sin agente) y servicios nativos con un puente. Cada una responde a una pregunta distinta.</p>

### AWS

| Tema | Recomendación | Evidencia |
| --- | --- | --- |
| EC2 y sistemas operativos | Alloy como servicio con `prometheus.exporter.unix`; `resourcedetection` con detector EC2 para metadatos | {{V}} componentes en las listas |
| EKS | Chart de Kubernetes Monitoring; credenciales por rol de la cuenta y no por claves largas | {{I}} |
| CloudWatch y servicios nativos | Cloud Provider Observability sin agente: rol IAM con `external_id` y scrape jobs por región; alternativa con metric streams por Firehose | {{V}} |
| Alternativa con agente | `prometheus.exporter.cloudwatch` y `loki.source.awsfirehose` en Alloy; `awscloudwatch` y `awss3` en Contrib | {{V}} |
| Métricas de servicios administrados | Preferir la integración administrada a un exporter propio salvo que se necesite control fino | {{I}} |

### Azure

| Tema | Recomendación | Evidencia |
| --- | --- | --- |
| Máquinas virtuales | Alloy como servicio con `prometheus.exporter.windows` o `.unix`; `discovery.azure` | {{V}} |
| AKS | Chart de Kubernetes Monitoring | {{V}} |
| Azure Monitor | Cloud Provider Observability sin agente con credencial de Service Principal; alternativa `prometheus.exporter.azure` o el receiver `azure_monitor` de Contrib | {{V}} |
| Logs de servicios | `loki.source.azure_event_hubs` en Alloy; `azure_event_hub` en Contrib | {{V}} |
| Identidades administradas | Alloy lista autenticaciones `basic`, `bearer`, `oauth2`, `sigv4`, `google` y `headers`; no hay componente específico de identidad administrada de Azure en su lista; Contrib puede cubrirlo con otra extensión | {{N}} validar en piloto |

### Cuándo usar cada camino

| Camino | Úselo cuando |
| --- | --- |
| OTLP | La aplicación es suya y se instrumenta; se quiere trazas, métricas y logs con contexto compartido |
| Prometheus exporters | Es infraestructura, base de datos o software de terceros que no se puede instrumentar |
| Integración administrada de Grafana Cloud | Se quiere métricas de servicios de nube sin operar un agente; el trabajo vive en IAM y Terraform |
| Servicio nativo del proveedor (CloudWatch, Azure Monitor) | La fuente de verdad es el proveedor y la alerta ya vive allí; se integra por scrape job o stream |

### Ventajas del backend frente a las del agente

| Ventaja | Viene de Grafana Cloud (backend) | Viene de elegir Alloy (agente) |
| --- | --- | --- |
| Integraciones administradas de nube sin agente | Sí | No |
| Span metrics y service graphs administrados | Sí | No |
| Adaptive Metrics, Logs y Traces | Sí | No |
| Chart de Kubernetes Monitoring con Fleet integrado | No | Sí |
| `prometheus.exporter.*`, clustering, eBPF y perfiles | No | Sí |
| Database Observability con `database_observability.*` | Parcial | Sí |
